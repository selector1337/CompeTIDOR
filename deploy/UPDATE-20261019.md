# Metas com preços automáticos e reinício de emergência

## Aplicar o código

Depois que esta versão estiver disponível no seu repositório, execute no servidor novo:

```bash
cd /opt/competidor
git status --short
git pull --ff-only
sudo systemctl restart competidor
curl --fail --max-time 10 http://127.0.0.1:8770/api/live
```

Se o Git informar alterações locais, preserve-as antes de atualizar. Não use `reset --hard`.
O arquivo `goal_pricing.py` precisa acompanhar `server.py`. Não há dependências Python novas.
Recarregue o navegador com Ctrl+F5. Nenhuma regra é ativada pela atualização.

## Instalar a recuperação independente (uma vez)

Esta configuração usa o usuário `www-data` e o diretório `/var/lib/competidor`, como o serviço fornecido pelo projeto. Confira:

```bash
sudo systemctl show competidor -p User
sudo -u www-data test -r /var/lib/competidor/app.json
sudo -u www-data test -r /var/lib/competidor/sessions.json
cd /opt/competidor
sudo bash deploy/install-recovery.sh
```

O instalador copia o auxiliar para um diretório pertencente a root e instala uma autorização sudo restrita ao comando `systemctl restart competidor.service`. O serviço principal mantém `NoNewPrivileges=true`; o auxiliar separado executa o reinício. Nenhum comando arbitrário é aceito pela API.

No arquivo Nginx **do CompeTIDOR no servidor novo**, adicione dentro do bloco `server` HTTPS, junto às outras `location`:

```nginx
include /etc/nginx/competidor-recovery.inc;
```

Não inclua no bloco HTTP nem nos domínios das outras aplicações. Para a instalação padrão:

```bash
sudo cp -a /etc/nginx/sites-available/competidor /etc/nginx/sites-available/competidor.backup-20261019
sudo nano /etc/nginx/sites-available/competidor
sudo nginx -t && sudo systemctl reload nginx
sudo systemctl status competidor-recovery --no-pager
```

Como Master ou Administrador, abra **Contas → Recuperação da aplicação → Abrir reinício de emergência**. A página também pode ser guardada nos favoritos: `https://competidor.umsoftware.com.br/recovery/`. Ela funciona com uma sessão válida mesmo quando o processo principal não responde. Reiniciar exige confirmação e há um intervalo mínimo de três minutos entre solicitações. Uma sessão expirada exige novo login ou acesso SSH.

Se o domínio ou diretório de dados for diferente, configure `RECOVERY_ORIGIN=https://seu-dominio` e `COMPETIDOR_DATA_DIR` no ambiente do auxiliar. O auxiliar lê `/etc/competidor.env`; instalações com outro arquivo de ambiente devem ajustar a unidade antes de iniciar. Sua porta 8771 escuta apenas em localhost e não deve ser aberta no firewall.

Para diagnóstico (não provoca reinício):

```bash
sudo journalctl -u competidor-recovery -n 40 --no-pager
sudo -u www-data sudo -n -l /usr/bin/systemctl restart competidor.service
```

O botão interrompe operações em andamento. Depois do retorno, confira os resultados antes de repetir uma publicação ou alteração. Ele é uma ferramenta de recuperação; não elimina a causa de um travamento.

## Usar os preços automáticos

1. Cadastre e salve uma meta mensal do SKU.
2. Em **Metas de venda**, abra **Preços automáticos** no SKU.
3. Defina o intervalo sem vendas, a redução em R$ ou %, a pausa após uma venda e pelo menos um limite: preço mínimo ou margem mínima.
4. Use **Salvar e ativar** e confirme o alcance: todas as contas conectadas e ambas as modalidades, incluindo anúncios pausados. Anúncios encerrados não recebem reduções. Novos anúncios compatíveis são incluídos automaticamente.

Cada anúncio registra seu preço original na primeira conferência com o Mercado Livre. A primeira redução ocorre após o intervalo configurado. Vendas de qualquer conta conectada contam para a meta e para a pausa. A redução percentual incide sobre o preço atual de cada anúncio; o piso de preço é comum ao SKU.

Com o ajuste de 21/10/2026, atingir a meta ou mudar de mês não restaura os preços nem reinicia o intervalo. A regra continua seguindo os limites e a pausa após vendas. Remover a meta também não restaura preços nem desativa uma regra já habilitada: use Pausar para interrompê-la. O preço original permanece registrado e só é restaurado por solicitação manual. O histórico de preços fica no acompanhamento da regra; as vendas históricas permanecem nas metas.

**Pausar** mantém os preços atuais. **Restaurar preços e desativar** volta aos originais, inclusive se houve alteração manual, mediante confirmação. Para editar uma regra existente que já alterou preços, restaure primeiro. Uma alteração manual detectada bloqueia aquele anúncio para impedir sobrescrita automática.

A margem usa a mesma definição do painel: `(preço − tarifa − frete − custo) / (preço − tarifa − frete) × 100`. Sem custo, tarifa ou frete confirmado, uma regra com piso de margem não reduz. Quando o próximo passo ultrapassaria a margem mínima, mantém o último preço válido. O piso não garante margem durante promoções externas ou alterações de custos posteriores.

O processamento é em segundo plano, em lotes limitados, e continua sem o navegador aberto. Vendas são reconferidas periodicamente; dados antigos/incompletos suspendem reduções. Falhas temporárias têm espera antes de nova conferência. Respostas incertas são reconciliadas com o preço remoto antes de novas alterações. O acompanhamento informa pendências por anúncio; não há promessa de aplicação simultânea em todas as contas.

Faça backup de `/var/lib/competidor/goal_pricing.json` junto aos demais dados. Ele guarda regras, preços originais e operações pendentes. Não o exclua com regras ativas. Para voltar a uma versão anterior do código, restaure/desative as regras antes.

Validação local: testes automatizados com APIs simuladas e interface em navegador. A publicação e o reinício reais do servidor não foram executados nesta implementação.

## Conferir os logs de preços

Em **Metas de venda → Preços automáticos → Acompanhamento dos preços**, consulte o resumo do último resultado por anúncio e a tabela com conta, modalidade, preço confirmado, preço pendente e mensagem. Use **Atualizar acompanhamento** para conferir o processamento sem perder o formulário.

O histórico mostra data/hora, anúncio, conta, preço anterior, preço solicitado/confirmado e resultado. Há filtros para confirmações, falhas, pendências, bloqueios e situações sem alteração, com páginas de 20 eventos. Envio preparado ou resposta incerta não contam como sucesso. Uma confirmação posterior ao timeout também é registrada, preservando o preço anterior do envio.

São mantidos os últimos 1.000 eventos por SKU no arquivo `goal_pricing.json`, inclusive ao editar uma regra. Falhas antigas anteriores a esta atualização não podem ser reconstruídas; o histórico existente de alterações confirmadas é preservado. Os contadores descrevem o último resultado conhecido de cada anúncio, não garantem que todos já participaram de um novo ciclo. O histórico completo só é carregado ao abrir o SKU para não sobrecarregar a listagem de metas.

### Retentativas de preço

Falhas têm nova conferência prevista após cinco minutos, sem limite fixo de tentativas enquanto a regra estiver ativa e as condições permitirem. A pendência fica salva e sobrevive ao reinício. Antes de reenviar, a automação consulta o preço: se já foi aplicado, confirma o resultado e não repete o desconto; se permanece no valor anterior, reavalia as condições no ciclo seguinte (a partir de 15 segundos), sem outra espera de cinco minutos. Os lotes e o tempo de resposta da API podem adiar o processamento.

Uma venda recente, pausa da regra, alteração externa de preço, dados de vendas desatualizados ou limite de margem/preço impedem reduções indevidas. A restauração do original também tem retentativa. O acompanhamento informa o total de envios de preço e a data da próxima conferência prevista; os números começam a ser registrados nesta atualização, sem reconstruir envios antigos.

Rejeições persistentes da API, permissões e cadastros inválidos precisam de correção: retentativa não garante que o Mercado Livre aceitará uma alteração. Não há registro de sucesso sem confirmação.
