# Atualização de 23/09/2026

Enviar para /opt/competidor preservando as pastas:

- server.py
- public/app.js
- public/official-stores.js
- public/index.html
- public/styles.css

Reiniciar o backend:

```sh
sudo systemctl restart competidor
curl --fail http://127.0.0.1:8770/api/health
```

No bloco `upstream competidor_backend` da configuração Nginx ativa, acrescentar
`keepalive_timeout 15s;` abaixo de `keepalive 32;`, conforme o modelo
deploy/nginx-competidor.conf. Preservar os blocos HTTPS e certificados existentes.
O timeout ocioso do backend deve permanecer maior que 15 segundos (padrão: 30).

```sh
sudo nginx -t && sudo systemctl reload nginx
```

Atualizar o navegador com Ctrl+F5. Retomar os lotes existentes. Quando houver
campos pendentes, preenchê-los na linha e clicar em Retomar / conferir pendências.
A revisão nos detalhes para suporte será `store-clear-pending-v4`.
As medidas informadas sem unidade agora recebem cm/g; o lote preserva
características personalizadas das variações e apresenta pendências em cartões.
Os detalhes técnicos ficam disponíveis para download no botão de suporte.

O healthcheck agora informa `ok: true` enquanto o serviço responde e `ready: false`
quando os pools estão ocupados, evitando que carga normal provoque reinícios pelo
monitor. As duas informações não são equivalentes.

Os logs enviados de produção confirmam reinícios solicitados pelo
competidor-healthcheck às 11:59:39, 12:03:49 e 12:09:45, seguidos dos erros do
proxy. A consulta de andamento também deixou de copiar históricos completos
para autenticar cada chamada; resultados grandes são copiados fora do bloqueio
compartilhado com progresso e saúde. Não é necessário desativar o monitor nem
aumentar os limites de memória para aplicar esta correção.

As alterações foram verificadas localmente, não em produção. Para investigar
qualquer 502 restante, correlacionar o horário com:

```sh
sudo journalctl -u competidor -n 120 --no-pager
sudo tail -n 60 /var/log/nginx/error.log
sudo journalctl -k --since '2 hours ago' --no-pager
```

Referência do Nginx para o timeout das conexões ociosas:
https://nginx.org/en/docs/http/ngx_http_upstream_module.html#keepalive_timeout
